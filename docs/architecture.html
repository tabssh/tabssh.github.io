Architecture & Technical Details

Deep dive into TabSSH's technical architecture and engineering decisions across both clients.

TabSSH ships as two separate codebases sharing the same data model and security stance. Android (tabssh/android) — Kotlin, MVVM, Room, JSch — beta, bug-fix phase. Desktop (tabssh/desktop) — Rust, egui, russh, async-tokio — v0.1.0 in development, ~50% complete.

🏗️ Application Architecture

MVVM Pattern

  • Model: Data layer with Repository pattern
  • View: Activities, Fragments, custom Views
  • ViewModel: Business logic with LiveData / Flow

Modular Structure

🔐 Security Architecture

Credential Storage

  • Android Keystore: hardware-backed key storage on supported devices
  • AES-256-GCM: all stored credentials encrypted at rest
  • Biometric Auth: fingerprint/face unlock for credential access
  • PIN code lock: separate PIN-only app lock (Wave 3.2)
  • Screenshot protection: FLAG_SECURE on sensitive activities
  • Cloud tokens off-DB: imported-cloud provider tokens (DO/Hetzner/Linode/Vultr) live in Keystore under cloud_token_${id} — never in the SQLite database

Key Management

  • OpenSSH (modern), PEM (PKCS#1), PKCS#8, PuTTY v2/v3 format support
  • Automatic format detection
  • RSA, ECDSA, Ed25519, DSA
  • OpenSSH user certificate auth (Wave 2.2 — stored_keys.certificate)
  • Secure in-app generation via Android crypto providers + BouncyCastle 1.77

Sync Encryption

  • AES-256-GCM with PBKDF2 (100,000 iterations) for the SAF sync file
  • Custom TABSSH_SYNC_V2 format with embedded salt + IV
  • 3-way merge with conflict UI (most apps just do last-write-wins)

Crash + ANR Capture

  • Daemon-thread ANR watchdog logs main-thread freezes >5s with full stack trace
  • Global uncaught-exception handler writes crash + opens CrashReportActivity on next launch
  • Auto-on for debug builds, opt-in for release builds (Settings → Logging)

🖥️ Terminal Emulation

VT100/ANSI Implementation

  • Complete escape sequence support
  • 256-color terminal support
  • Unicode and UTF-8 handling
  • Configurable scrollback buffer
  • xterm-256color compatibility

📱 Mobile Optimization

Android Integration

  • Intent handling for SSH URLs
  • App shortcuts for quick connections
  • Quick Settings tile support
  • Background operation with battery optimization

Performance

  • Efficient memory management
  • Connection pooling
  • 60 FPS terminal rendering
  • Network compression support

💻 Desktop Architecture 💻 Desktop

Single static Rust binary, async I/O on Tokio, egui for the UI, russh for the SSH transport, OS keychain for credential storage. Currently v0.1.0 in active development — the items below are wired into Cargo but not all are user-facing yet (per the comparison table in desktop/CLAUDE.md).

🏗️ Application Architecture

Async-First, egui Immediate Mode

  • Runtime: Tokio multi-threaded executor; SSH I/O on a worker pool, UI on the main thread
  • UI: egui + eframe 0.25 (immediate-mode, pure Rust, no native widget toolkit dependency)
  • Cross-thread state: Arc<Mutex<…>> for shared session state; channel-based events for UI updates
  • Single binary: static linking, panic = "abort" + LTO + strip in release for ~8–14 MB output

Module Structure

src/
├── app.rs          # Top-level egui App impl + window state
├── main.rs         # Entry — env_logger init, eframe::run_native
├── lib.rs          # Library boundary for tests + benches
├── ssh/            # russh client, auth, channel multiplexing
├── sftp/           # russh-sftp wrapper, transfer queue
├── terminal/       # vte parser + grid + scrollback
├── ui/             # egui panels, dialogs, tab strip, palettes
├── config/         # ~/.ssh/config (ssh2-config), TabSSH settings (TOML)
├── storage/        # rusqlite — connections, history, snippets
├── crypto/         # AES-256-GCM, PBKDF2 for sync blob
├── platform/       # OS-specific paths, tray hooks, keychain glue
├── bin/            # Optional ancillary binaries
└── utils/          # Logging, error types, helpers

🦀 Core Crates

  • SSH transport: russh 0.40 + russh-keys 0.40 — pure-Rust SSH 2.0, no JNI
  • SFTP: russh-sftp 2.0 (wired; UI surface in progress)
  • Terminal: vte 0.13 — VT/xterm parser; grid + scrollback implemented in terminal/
  • UI: eframe + egui 0.25 with egui_extras for image rendering
  • Storage: rusqlite 0.30 (bundled SQLite, no system dep)
  • SSH config: ssh2-config for round-trip ~/.ssh/config parsing (planned wiring)
  • Async: tokio 1.35 with full features, async-trait for the channel interface
  • Path expansion: shellexpand for ~ + env-var resolution
  • Errors: anyhow at the boundary, thiserror for typed module errors

🔐 Security Architecture

Credential Storage

  • OS Keychain: keyring 2.1 abstracts macOS Keychain / Windows Credential Manager / Linux Secret Service behind a single API
  • macOS-specific: security-framework 2.9 for direct Keychain interop where the generic crate isn't enough
  • Windows-specific: windows 0.52 with Win32_Security_Credentials features
  • At-rest crypto: AES-256-GCM via the aes-gcm crate, PBKDF2 (100k) for the sync-blob KDF — same parameters as the Android side, so encrypted blobs round-trip

Memory Safety

  • Rust compile-time guarantees eliminate the buffer-overflow / use-after-free class entirely
  • panic = "abort" in release: a panic terminates the process rather than unwinding through unsafe state
  • No unsafe blocks in the app layer (Crypto / FFI crates are reviewed dependencies)

Crash Handling

  • Custom panic hook writes a backtrace + thread name to the OS state directory: ~/.local/state/tabssh/crashes/ (Linux), ~/Library/Logs/tabssh/ (macOS), %LOCALAPPDATA%\tabssh\crashes\ (Windows)
  • No "ANR watchdog" equivalent — desktop relies on the OS process monitor

🖥️ Terminal Emulation

  • Parser: vte 0.13 — same parser used by Alacritty/wezterm; full VT100/xterm-256color escape coverage
  • Grid: custom row/column buffer with double-width / wide-char handling; scrollback implemented in-tree
  • Renderer: egui draws the grid as a textured glyph atlas; native font rendering at any size
  • 24-bit colour: supported (matches mobile after Wave 4)
  • Unicode: full UTF-8; unicode-width-style accounting in the grid

🐳 Build & Distribution

  • Docker-first: all builds happen via make build in containers — no local Rust toolchain assumed
  • Targets: Linux amd64/arm64, macOS amd64/arm64, Windows amd64/arm64, FreeBSD amd64/arm64, OpenBSD amd64/arm64, NetBSD amd64 — 11 binaries per release
  • Static linking: Linux uses musl targets; macOS / Windows / BSD use their default static toolchains
  • Asset naming: tabssh-{os}-{arch} (with .exe on Windows) — matches the PLATFORMS regex in this site's js/main.js
  • Binary size: ~8–14 MB after LTO + strip

🧪 Current Status

  • ✅ Working today: SSH connect / auth (password, public key, keyboard-interactive), terminal I/O via russh + vte, basic UI with tab strip, ~/.ssh/ direct read
  • 🚧 In progress: SFTP UI surface, OS keychain wiring, theme system (JSON format shared with mobile), port forwarding, command palette
  • 📋 Planned: Mosh client in pure Rust (avoid the cross-compile dance the Android app does for libmosh-client.so), X11 forwarding via x11rb, hypervisor support, sync
  • ❌ Won't ship: on-screen keyboard, swipe gestures, foldable layouts (mobile-only patterns)
