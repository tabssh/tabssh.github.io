Architecture & Technical Details

Deep dive into TabSSH's technical architecture and engineering decisions.

🏗️ Application Architecture

MVVM Pattern

  • Model: Data layer with Repository pattern
  • View: Activities, Fragments, custom Views
  • ViewModel: Business logic with LiveData / Flow

Modular Structure

app/src/main/java/io/github/tabssh/
├── ui/             # Activities, fragments, adapters, dialogs, views
├── ssh/            # SSH auth, connection, forwarding, config parsing
├── terminal/       # Termux-based emulator + custom keyboard
├── crypto/         # Key parsing, generation, storage
├── storage/        # Room database (v23) + entities + DAOs
├── themes/         # 23 built-in themes + parser + validator
├── sync/           # SAF-based universal cloud sync
├── sftp/           # File transfer manager + remote file editor
├── services/       # SSH foreground service
├── protocols/      # Mosh, X11, Telnet
├── hypervisor/     # Proxmox / XCP-ng / Xen Orchestra / VMware
├── cloud/          # DigitalOcean / Hetzner / Linode / Vultr import
├── backup/         # Encrypted ZIP export/import
├── accessibility/  # TalkBack, contrast, navigation
├── network/        # Security, proxy, detection
└── utils/          # Logging (with ANR watchdog), performance, helpers

🔐 Security Architecture

Credential Storage

  • Android Keystore: hardware-backed key storage on supported devices
  • AES-256-GCM: all stored credentials encrypted at rest
  • Biometric Auth: fingerprint/face unlock for credential access
  • PIN code lock: separate PIN-only app lock (Wave 3.2)
  • Screenshot protection: FLAG_SECURE on sensitive activities
  • Cloud tokens off-DB: imported-cloud provider tokens (DO/Hetzner/Linode/Vultr) live in Keystore under cloud_token_${id} — never in the SQLite database

Key Management

  • OpenSSH (modern), PEM (PKCS#1), PKCS#8, PuTTY v2/v3 format support
  • Automatic format detection
  • RSA, ECDSA, Ed25519, DSA
  • OpenSSH user certificate auth (Wave 2.2 — stored_keys.certificate)
  • Secure in-app generation via Android crypto providers + BouncyCastle 1.77

Sync Encryption

  • AES-256-GCM with PBKDF2 (100,000 iterations) for the SAF sync file
  • Custom TABSSH_SYNC_V2 format with embedded salt + IV
  • 3-way merge with conflict UI (most apps just do last-write-wins)

Crash + ANR Capture

  • Daemon-thread ANR watchdog logs main-thread freezes >5s with full stack trace
  • Global uncaught-exception handler writes crash + opens CrashReportActivity on next launch
  • Auto-on for debug builds, opt-in for release builds (Settings → Logging)

🖥️ Terminal Emulation

VT100/ANSI Implementation

  • Complete escape sequence support
  • 256-color terminal support
  • Unicode and UTF-8 handling
  • Configurable scrollback buffer
  • xterm-256color compatibility

📱 Mobile Optimization

Android Integration

  • Intent handling for SSH URLs
  • App shortcuts for quick connections
  • Quick Settings tile support
  • Background operation with battery optimization

Performance

  • Efficient memory management
  • Connection pooling
  • 60 FPS terminal rendering
  • Network compression support
